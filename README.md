# MyCareer.AI

An AI placement companion for job seekers in India: **upload a resume → answer only what the AI can't work out → get matched jobs with honest explanations → apply with a truthful, tailored resume → track everything.** Live at https://app.tiaslab.in. Roadmap: [ROADMAP.md](ROADMAP.md).

## Deploy to Render (free plan + Firestore backup)

1. **Firebase** (project `my-career-ai`):
   - Build → Firestore Database → *Create database* (production mode, region `asia-south1`). Keep the default rules that deny all client access — only the server touches Firestore.
   - Project settings → Service accounts → *Generate new private key*. Keep the JSON file private.
   - Authentication → Settings → Authorized domains → add `app.tiaslab.in` (and your `*.onrender.com` address).
2. **Render**: New → *Blueprint* → pick this repository. `render.yaml` sets everything up; when asked, paste:
   - `FIREBASE_SERVICE_ACCOUNT_JSON` — the whole service-account JSON on one line
   - `ADMIN_EMAILS` — who can open Admin (comma-separated)
   - `GEMINI_API_KEY` — optional shared AI key (users can add their own free key in the app)
   `APP_SECRET` is generated by Render; **never change it** after launch (it encrypts stored keys).
3. **Domain**: Render → Settings → Custom domains → `app.tiaslab.in`, then add the CNAME it shows at your DNS provider.
4. **Search Console**: verify `app.tiaslab.in` and submit `https://app.tiaslab.in/sitemap.xml`.
5. **Google Analytics**: mark the key events listed in `src/lib/analytics.ts`.

**How data is stored.** The app works from a fast local data file and keeps a compressed backup in Firestore (`_snapshots` collection, `server/db/snapshot.ts`): people's data within ~15 seconds of a change, jobs every ~20 minutes, and everything on shutdown. A restart restores it with a handful of reads, so it stays well inside Firestore's free quota. (`STORE_MODE=firestore` switches to reading/writing Firestore directly — only sensible on a paid plan.)

**Free-plan limits.** Render's free instance sleeps after 15 minutes without visitors; while asleep, hourly job discovery and alerts pause, and the first visit takes ~30–60 s to wake it. Discovery runs again 15 s after every wake-up. To keep it awake (one free service fits Render's 750 free hours a month), point a free uptime monitor such as UptimeRobot or cron-job.org at `https://app.tiaslab.in/api/health` every 10 minutes — or move to the Starter plan when you have users.

## Quick start (local development)

```powershell
npm install
copy .env.example .env      # then edit (see below)
npm run dev                 # API + UI on http://localhost:3000
```

Requires Node 20+. Everything works with **no AI keys** (deterministic parsing, matching, tailoring and a basic chat). Add keys to unlock the AI layer:

| Variable | Purpose |
|---|---|
| `GEMINI_API_KEY` | Primary AI provider (server-side; users never supply keys) |
| `FALLBACK_AI_API_KEY` + `FALLBACK_AI_BASE_URL` + `FALLBACK_AI_MODEL` | Second provider, any OpenAI-compatible API (Groq, OpenRouter, …). Used automatically if the first is down or rate-limited |
| `FIREBASE_SERVICE_ACCOUNT_JSON` or `GOOGLE_APPLICATION_CREDENTIALS` | Persist to Firestore. Without it a local JSON file (`data/store.json`) is used — **dev only** |
| `ADMIN_EMAILS` | Who sees the Admin tab |
| `SITE_URL` | Public address for canonical links, sitemaps and share tags (default `https://app.tiaslab.in`) |
| `ADZUNA_APP_ID` / `ADZUNA_APP_KEY` | Optional official job API (free key) |

**Local dev without Google sign-in:** set `DEV_AUTH_BYPASS=true` and open `http://localhost:3000/?dev=alice`. This is refused when `NODE_ENV=production`.

Production: `npm run build` then `NODE_ENV=production npm start` (needs real Firebase credentials — Auth verifies ID tokens for project `my-career-ai`).

## Job sourcing engine (v5)

Jobs come only from sources that allow it. Nothing is scraped from portals whose terms forbid it (Naukri, LinkedIn, Indeed…); users bring those jobs in by link, and the app gives them pre-filled search links to every major portal.

| Layer | What | Where |
|---|---|---|
| Company registry | Employers hiring in India, each with its careers system and board id. Seeded with ~120 boards verified live (`npm run probe:companies -- --write`), grown from Admin → Company registry by pasting a careers URL | `server/jobs/registry.ts`, `server/jobs/seed/companies.json` |
| Careers-system connectors | Greenhouse, Lever, Ashby, SmartRecruiters, **Workday**, **Oracle Recruiting**, Recruitee, Workable, and any careers page publishing schema.org `JobPosting` data (robots.txt respected). Boards rotate least-recently-fetched first | `server/jobs/connectors.ts`, `server/jobs/ats.ts` |
| Detection | Careers URL → system + board id, including systems embedded in or linked from the page. Darwinbox (blocks bots) and job portals are recognised and declined | `server/jobs/detect.ts`, `npm run detect:ats -- <url>` |
| Aggregators | Adzuna, Careerjet, Jooble (free keys, pasted in Admin or .env; off until set), Remotive, Arbeitnow, Himalayas, Remote OK, Jobicy | `server/jobs/aggregators.ts` |
| Quality | ~170 Indian cities incl. old names, states, Pan-India, multi-city postings; salary per year/month/day/hour with the posting's own wording; 24 job categories incl. frontline work; minimum education (10th → PG); freshers; scam signals (deposits, kit fees, pay-per-week bait); cross-source dedupe; closed-job detection when a full board stops listing a job | `server/nlp/location.ts`, `server/jobs/normalize.ts`, `server/jobs/classify.ts`, `server/jobs/ingest.ts` |
| Search | In-process Orama index: typo-tolerant full text, Indian job synonyms ("delivery boy" ↔ "delivery partner" ↔ "rider"), filters, facets, "best match for me" sort blending relevance with the personal match score | `server/search/` |

## Safety properties (all covered by automated tests)

- **No fabricated resume content.** Every skill, bullet, number, employer, title, date, certification and education entry in a tailored resume is checked against the profile; invalid output is repaired or replaced by a deterministic version, and an invalid resume cannot be approved.
- **Nothing is submitted for you.** Applying opens the employer's page; the app tracks status. Sensitive agent actions require a UI confirmation the model cannot give itself.
- **Prompt-injection resistant.** Job/resume text is fenced as untrusted data; after reading external text, preference/status changes downgrade to confirmations.
- **User isolation.** Every query is scoped by the authenticated `uid`; agent tools take no user-id argument.
- **Graceful degradation.** AI down or credits exhausted → deterministic parsing/matching/tailoring and a basic-mode chat still work. One failing job source never affects others.
- **SSRF-safe** job-URL import; resume uploads validated by content, not extension.
